- **比對方式**：在 v3.1.0 部署前，先記下舊版 API 的結果作為基準，存放在 `dbbackup/261020/old_api_baseline/`。這次把同一份資料還原到本機後，用 v3.2.0 重新比對。
- **結果**：238 項中 237 項完全相同。
- **唯一不同的一項是 `fail-analysis[all]`**：兩列內容相同，只是順序對調。這兩列是 `WIFI_TX_VERIFY_ALL / EVM fail` 的 ERR_29 和 ERR_33，次數都是 70 次。
  - 原因：失敗分析只依次數排序，次數相同時沒有規定先後，所以順序本來就不固定。

### 9.2 唯一失敗：test_99（瀏覽器主控台有 1 筆 400）

- **來源**：test_02 在 AI 報告視窗按「和上一份比較」，`GET /api/reports/5101-260915007/compare` 回 400。
- **原因**：比較至少需要兩份報告。測完已把測試產生的報告刪除（Q73），所以這張工單只剩 10/20 上傳時產生的 1 份。
- **畫面**：顯示「At least two reports are needed to compare.」（截圖已確認），沒有壞掉，只是瀏覽器把 400 回應記成主控台錯誤。
- **不是 3.2.0 造成的**：這段程式從 3.0.0 起就沒改過。本機測試資料裡同一張工單有多份報告，所以之前沒遇到。
- **比較功能本身**：整合測試在有兩份報告時驗證過，回 200，同樣的資料比較結果沒有差異。
- **可以改善的地方**：只有一份報告時停用「和上一份比較」按鈕，就不會送出這個請求。這要改程式並重新部署，這次沒有做。
